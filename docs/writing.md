# 記事の書き方

`content/articles/<カテゴリ>/<スラッグ>.md` を作る。カテゴリは `site.json` の slug(aio / seo / glossary / ads / analytics / lp-creative / cost / news)。

```markdown
---
title: AIOとは?SEOとの違いと今日からできる対策
seo_title: (省略可。検索結果用に title と変えたいときだけ)
description: AIO(AI検索最適化)の意味、SEO・LLMO・GEOとの違い、ChatGPTやAI Overviewsで引用されるための対策を実例つきで解説します。
date: 2026-11-10
updated: 2026-11-10
summary: AIOは、ChatGPT や Google の AI Overviews などのAI検索で、自社の情報が引用・紹介されるように整える取り組みです。
author: (省略可。省略するとサイト名の編集部)
draft: (true にすると公開しない)
---
最初の段落で定義・結論を言い切る。

## AIOとは?
...

## よくある質問
### AIOとSEOはどちらを先にやるべき?
答え。
```

## ド素人が読んでもわかるように書く(2026-11-09 Nori さんの要望)

「小学生が読んでもわかるように」「ド素人が読んでも理解できるように」がサイト全体の方針。

- **最初に身近なたとえ**:図書館と司書さん、USB-C、お店の看板など。冒頭の段落か最初の H2 で「ひとことで言うと」を書く。
- **短い文**:1文に言いたいことは1つ。「〜ので、〜が、〜ため」と長くつながない。
- **専門用語は初めて出たところで説明する**:「クロール(ページを見に行くこと)」のように。英語の略語は読み方も書く。説明なしで使ってよいのは、その記事で説明ずみの言葉だけ。
- **図を1枚以上**:流れ・比較・たとえは図にする(書き方は下の「図解を入れる」)。表より図のほうがわかりやすいところは図にする。
- **むずかしい話は後ろへ**:正式な用語の対応表、仕様の細部、コード、検証方法は記事の後半の `[上級]` 章にまとめる。前半の `[初級]` は、コードがなくても読める形にする。
- **やることは「どこを開いて、何を押す」まで書く**:「設定する」で終わらせない。

### たとえ話の基準(2026-11-09 Nori さん「たとえ話のクオリティが大事」)

たとえ話は、この記事がわかるかどうかを決める一番大事な部分。次をすべて満たすものだけを使う。

1. **だれでも毎日見ているもの**:お店・図書館・郵便・料理・電車など。業界の道具、ゲーム、世代でちがう流行は使わない。
2. **しくみの対応が正しい**:「だれが・何を・どの順で・何のために」が本物と1対1で対応すること。対応しない部分(本物にはない登場人物や動き)はたとえに入れない。書く前に「たとえ ⇔ 本物」の対応表を作って確かめる。
3. **1記事に1つのたとえを通す**:最初に決めたたとえ(例:図書館)を最後まで使い、途中で別のたとえに乗りかえない。図と本文で同じたとえを使う。
4. **対応を図で見せる**:「図書館では / Googleでは」のような左右の対応表の図を1枚入れる(`tools/figures.py` の `pair_fig`)。
5. **たとえの限界を1文書く**:「ただし本物の司書さんとちがって、Google はお金をもらって順番を変えません」のように、たとえが当てはまらない所を書いて、誤解を残さない。
6. **正確さを優先**:かわいさやわかりやすさのために、事実とちがう動きをさせない。たとえだけ読んだ人がまちがった理解をしないかを、書いたあとに読み直して確かめる。

これまでに使ったたとえ(同じテーマはそろえる):Google検索=図書館と司書さん、MCP=USB-Cの差し込み口、robots.txt=入口の張り紙、サイトの3つのファイル=お店の張り紙・部屋の一覧表・おすすめ案内板、アクセス4種類=お店のお客さん・ガイドブックの取材・お使い・紹介で来た人、JavaScriptの表示=できあがったお弁当と材料+作り方メモ、一次情報=自分で行って食べた感想、冒頭で答える=道案内、引用の確かめ方=ガイドブックに自分の店がのっているか毎月確かめる、AIO・LLMO・GEO・AEO=今川焼き・大判焼きの呼び名ちがい、AI Overviews=司書さんが答えを先に教えてくれる、タイトルと説明文=本の題名と帯、canonical=あだ名と名簿の本名、サイトマップ=建物の部屋の一覧表、Search Console=サイトの通知表、E-E-A-T=修理のお店えらび、構造化データ=作文と履歴書。

左右の図で「同じもの」を対応させるときは `=`、「くらべる」ときは `vs` を使う(`pair_fig` の `sep`)。

## 初心者・中級者・上級者の全員に役立てる(2026-11-09 Nori さんの要望)

- H2 の末尾に `[初級]` `[中級]` `[上級]` を付ける。見出しにラベルが付き、冒頭に「レベル別の読み方」(はじめての方/設定・実務をする方/もっと深く知りたい方)が自動で出る。2つ以上のレベルがあるときだけ出る。
- 初級:専門用語をひとことで説明してから使う。たとえや表で全体像を見せる。
- 中級:設定の手順、コードの例、注意点。そのまま実務で使える形にする。
- 上級:仕様の細かい挙動、検証のしかた、研究や一次資料の中身、限界と注意点。記事に1つ以上入れる。
- 「よくある質問」にはラベルを付けない。

使える書き方:`## 見出し` `### 小見出し`、`- 箇条書き`、`1. 番号`、`| 表 |`、`> 引用`、```` ``` ```` コード、`**太字**`、`[リンク](URL)`、`![説明](/assets/img/xxx.png)`。

記事を足したら `content/roadmap.json` の関係するステップの `articles` にパスを足す(記事の末尾に「ロードマップの STEP n の解説です・次にやること」が出る)。

書いたら `python3 tools/build.py . && python3 tools/seo_check.py .`。

## 図解を入れる

- 図は `tools/figures.py` で SVG を作り、`content/figures/<名前>.svg` に置く(幅360の縦長。スマホで読める文字の大きさにする)。
- 本文では1行に `{{figure:名前|図1 キャプション}}` と書くと、build.py が図をそのまま埋め込む。色や文字の大きさは `assets/style.css` の `.fig .f-*` で決まる。
- 図の中の文字も事実確認の対象。数字や仕様を入れたら本文に出典を書く。
