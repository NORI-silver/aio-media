# ニュース記事の自動更新(毎日の手順)

最新情報は2段構えで届けます。

1. **3時間ごと(GitHub Actions `news-watch.yml`、AIなし)**:`content/news-sources.json` の公式ブログ・検索ステータスを読み、新着を `content/news-watch.json` にためて `/news/` の「公式発表の新着(自動更新)」に原文リンクで出す。
2. **毎日1回(Claude のスケジュール実行)**:下の手順で、大事な新着を日本語の解説記事にする。

## 毎日の手順

1. `main` を最新にして、`AGENTS.md` と `docs/writing.md` を読む。
2. `content/news-watch.json` の items のうち、`content/news-triage.json` にまだ載っていない URL を拾う。
3. 加えて WebSearch で、直近数日の SEO・AIO・広告の大きな動き(コアアップデート・スパムアップデート、AI Overviews / AI モード、ChatGPT・Perplexity・Gemini の検索機能、Search Console・GA4・Google 広告の仕様変更)がフィードの外で出ていないか確認する。見つけたら必ず公式の発表ページまでたどる。
4. 1件ずつ判断して `content/news-triage.json` に書く。
   - **書く**(`written:<スラッグ>`):中小企業のマーケ担当・SEO担当の実務に影響があるもの。コアアップデート・スパムアップデートの開始と完了、AI検索・クローラー・robots.txt の仕様変更、Search Console / GA4 / 広告の新機能や廃止、ポリシー変更。
   - **既存記事に追記**(`merged:<記事のパス>`):既存記事の内容が古くなる変更は、その記事を直して `updated:` を今日にする。
   - **見送り**(`skipped:<短い理由>`):イベント告知、海外だけの機能、製品の宣伝、実務に影響しないもの。
5. 記事は `content/articles/news/<英語スラッグ>.md`。1日の上限は3本。大きな話を1本しっかり書くほうを優先する。
6. `python3 tools/build.py . && python3 tools/seo_check.py .` で NG 0。ブランチを切って PR を出し、SEO check が緑ならマージする(AGENTS.md の standing approval)。

## ニュース記事の書き方

`docs/writing.md` のルールをすべて守ったうえで:

- **冒頭の段落で「何が・いつ・誰に影響するか」を言い切る**。日付は公式発表の日付(日本時間で書くときは明記)。
- **一次情報で確かめたことだけを書く**。公式ページ(Google 検索セントラル、検索ステータス ダッシュボード、Bing Blog、OpenAI など)を WebFetch で開いて確かめる。公式ページが開けず報道でしか確かめられない部分は「海外メディアの報道で確認」と書き分ける。噂や未確認の順位変動は「Google は認めていない」と明記するか、書かない。
- 出典リンクには確認日を添える(例:「2026年11月9日に確認」)。
- H2 にレベルを付ける:`何が変わった? [初級]` → `何をすればいい? [中級]`(手順・設定例) → 仕様の細部・一次資料の読み方・検証方法 `[上級]` を1章以上 → `## よくある質問`。
- 内部リンクを3本以上(関連する柱の記事、用語集、`/aio-checker/` など)。
- タイトルは28〜40字で、何の話か分かる語を前半に(例:「Google 2026年12月コアアップデート開始|影響と確認方法」)。
- 「私たちのサイトでは〜」のように、当サイトで実際に確認・対応したことがあれば書く。やっていないことを体験談として書かない。
- 続報(完了の発表など)は新しい記事を作らず、元の記事に追記して `updated:` を更新する。

## 発表元を増やすとき

`content/news-sources.json` に足す。`feed` が分からなければ `page` だけでよい(ページの RSS/Atom を自動で探す)。広い話題のフィードは `keywords` で絞る。どの発表元が読めているかは `content/news-watch.json` の `sources` で分かる。
