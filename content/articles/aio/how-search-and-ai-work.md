Google 検索は、**ページを見つけて取りに行く「クロール」、中身を理解して登録する「インデックス」、検索された言葉に合うページを並べる「検索結果の表示」の3段階** で動いています。ChatGPT の検索や Google の AI Overviews のような AI 検索も、多くはこの検索の仕組みを土台にして、質問を小さな検索に分け、見つけたページを読んで答えと出典リンクを作ります。

つまり、**AIO(AI検索最適化)は SEO とまったく別のものではなく、SEO の上に乗っている** と考えると全体がつかみやすくなります。この記事では、その流れを図で順番に説明します。内容は Google 検索セントラルや各社の公式ドキュメント(2026年11月9日に確認)にもとづいています。

この記事でいう AIO は、ChatGPT・Perplexity・Google の AI 機能など、AI が答えを作る検索全般に向けた最適化のことです(呼び方の整理は「[AIO・LLMO・GEO・AEOの違い](/aio/aio-llmo-geo-aeo-difference/)」)。

## Google検索はどうやってページを見つけて並べる? [初級]

{{figure:google-search-flow|図1 Google検索の流れ。見つける → クロール → レンダリング → インデックス → 表示の順に進む}}

Google の「[Google 検索の仕組みに関する詳細ガイド](https://developers.google.com/search/docs/fundamentals/how-search-works)」(2025年12月18日更新)によると、流れは次のとおりです。

1. **URLを見つける**:すでに知っているページのリンクをたどったり、サイト運営者が送った[サイトマップ](/seo/xml-sitemap/)を読んだりして、新しいページの URL を見つけます。全ページを登録した中央の名簿のようなものはありません。
2. **クロール**:Googlebot というプログラムがページを取りに行きます。[robots.txt](/aio/ai-crawler-robots-txt/) で禁止されているページは取りに行きません。
3. **レンダリング**:最近のバージョンの Chrome を使って JavaScript を実行し、人がブラウザで見るのと同じ画面を作ります。
4. **インデックス**:文章・タイトル・画像などを解析して、検索用のデータベース(インデックス)に登録します。内容がほぼ同じページが複数あるときは、その中から代表の1ページ(正規URL)を選びます(詳しくは「[canonical(正規URL)とは?](/seo/canonical-url/)」)。
5. **検索結果の表示**:検索されたら、インデックスの中から合うページを探し、検索語・ユーザーの場所・言語・端末など **数百の要因** をもとに並べます。

Google は、クロールもインデックスも表示も **保証はしない** とはっきり書いています。また、お金を払って順位を上げてもらうことはできません(広告枠は別です)。

## AI検索はどうやって答えを作る? [初級]

{{figure:ai-search-flow|図2 AI検索が答えを作る流れ。質問を小さな検索に分け、ページを読んで、出典つきで返す}}

Google の AI Overviews(AIによる概要)と AIモードについて、Google は「[AI features and your website](https://developers.google.com/search/docs/appearance/ai-features)」で次のように説明しています。

- 1つの質問から、関連する複数の検索を裏側で同時に行う **「クエリ ファンアウト」** という方法を使うことがある
- 参照するのは、**Google のインデックスに登録されていて、スニペット(説明文)を表示できるページ**
- 表示されるための特別な要件や、AI 向けの特別な最適化は必要ない

ChatGPT の検索も、OpenAI は OAI-SearchBot というクローラーでページを集めて検索に使うと説明しています([OpenAI のクローラー一覧](https://developers.openai.com/api/docs/bots))。細かい仕組みは各社で違いますが、「**前もって集めたページの索引から探し、読んで、答えと出典を返す**」という骨組みは共通しています。

だから AI 検索に引用されるためにも、まず **クロールされて、インデックスに入っていること** が前提になります。Google の AI 機能のくわしい話は「[AI Overviewsとは?](/aio/ai-overviews/)」にまとめています。

## AIの「学習」と「検索」は何が違う? [中級]

AI がウェブのページを使う方法は、大きく2種類あります。ここを混ぜると、robots.txt の設定を間違えやすくなります。

{{figure:training-vs-retrieval|図3 学習に使う場合と、検索して引用する場合の違い}}

| | ① 学習に使う | ② 検索して引用する |
|---|---|---|
| 何のため? | AI のモデル自体を作る・賢くする | 質問されたときに、最新の情報で答える |
| 主なクローラー | GPTBot(OpenAI)、ClaudeBot(Anthropic) | OAI-SearchBot(OpenAI)、PerplexityBot、Claude-SearchBot |
| 出典リンク | 付かない | 付く(サイトに人が来るきっかけになる) |
| 止めると? | 今後の学習に使われなくなる | その AI 検索の回答に出にくくなる |

出典:[OpenAI のクローラー一覧](https://developers.openai.com/api/docs/bots)、[Anthropic のクローラーの説明](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-the-web)、[Perplexity のクローラーの説明](https://docs.perplexity.ai/docs/resources/perplexity-crawlers.md)(いずれも2026年11月9日に確認)。

たとえば OpenAI は、OAI-SearchBot を拒否したサイトは ChatGPT の検索の回答に表示されない(ナビゲーション用のリンクとしては出ることがある)と説明しています。一方、GPTBot を拒否しても学習に使われなくなるだけです。「学習はいやだけど、AI検索には出たい」なら、学習用だけを止めることができます。Google については、学習用の Google-Extended を止めても Google 検索や AI Overviews には影響しません。

## SEOとAIOは結局どこが同じでどこが違う? [中級]

{{figure:seo-aio-layers|図4 SEOとAIOは「読まれる → 理解される → 選ばれる」の3段で考えると重なりが見える}}

ここまでの流れを、サイト側から見て3段にまとめるとこうなります。

1. **読まれる**:クロールを許可する、本文を最初の HTML に入れる、サイトマップを出す、表示を速くする。SEO と AIO でほぼ同じです。AIクローラーの多くは JavaScript を実行しないので、AIO ではとくに大事です(「[JavaScriptとAIクローラー](/aio/javascript-ai-crawlers/)」)。
2. **理解される**:問いの形の見出し、[構造化データ](/seo/structured-data/)、正規URL など、何のページかを機械にわかるようにする。これも共通です。
3. **選ばれる**:SEO では上位に表示されること、AIO では回答の出典として引用されること。どちらも、一次情報・冒頭での答え・信頼できる運営者情報が効いてきます(「[冒頭で答える書き方](/aio/answer-first-writing/)」「[E-E-A-Tとは?](/seo/eeat/)」)。

違いが出るのは主に3段目と、成果の測り方です。SEO は「順位とクリック」で測れますが、AI 検索では **引用されても、クリックされないことが多い** ので、引用された回数や AI からの流入を別に見る必要があります(「[AIに引用されているか確かめる方法](/aio/ai-citation-tracking/)」)。

## このサイトは今どの段階にいる? [中級]

このサイト(AIO対策ナビ)が図1のどこまで進んでいるかを、Search Console の URL 検査で確かめました(2026年11月9日)。

| ページ | Search Console の状態 | 図1でいうと |
|---|---|---|
| トップページ | 「送信して登録されました」。2026年11月9日にクロール、Google が選んだ正規URLとサイト側の指定が一致 | ⑤まで進める状態(インデックス済み) |
| 記事「AIO・LLMO・GEO・AEOの違い」 | 「検出 - インデックス未登録」 | URL は見つかったが、まだクロールされていない |

同じ日に公開したページでも、**トップページは登録済み、記事はまだ「見つけただけ」** という差が出ています。Google のヘルプでは「検出 - インデックス未登録」は、Google が URL を見つけたもののまだクロールしていない状態とされています。新しいサイトではよくあることで、内部リンクやサイトマップでページを見つけやすくして待つのが基本です。この結果は、インデックスが進んだらこの記事で更新します。

この確認は、Search Console の画面ではなく、AI から MCP という仕組みで Search Console に問い合わせて行いました。その方法は「[MCPとは?](/glossary/mcp/)」で説明しています。

## 仕組みを知ったうえで、上級者は何を確かめる? [上級]

仕組みがわかると、「どの段で止まっているか」を切り分けて調べられるようになります。

| 止まっている段 | 確かめ方 | 主な原因 |
|---|---|---|
| 見つける | Search Console の「ページ」レポートで URL が出てくるか | 内部リンクがない、サイトマップに入っていない |
| クロール | URL 検査の「クロール」欄、サーバーのアクセスログ | robots.txt の拒否、サーバーエラー、AIクローラーのブロック(CDN の設定も含む) |
| レンダリング | URL 検査の「ライブテストのスクリーンショット」、`curl` で取った HTML に本文があるか | 本文が JavaScript の実行後にしか出ない |
| インデックス | URL 検査の「ページのインデックス登録」、Google が選んだ正規URL | 重複・薄い内容・noindex・正規URLの食い違い |
| 表示・引用 | Search Console の検索パフォーマンス、AI 検索で実際に質問 | 問いに答えていない、一次情報がない、信頼の手がかりが弱い |

とくに AIO では、**Google の段階と各 AI サービスの段階が別々に進む** ことに注意します。Googlebot には読まれていても、CDN のボット対策で OAI-SearchBot だけ止まっている、ということがあります。サーバーのアクセスログで、各クローラーの User-Agent ごとにステータスコード(200 か 403 か)を見るのが確実です。ボットの名前は偽装できるので、本物かどうかは各社が公開している IP アドレスの一覧で確かめます(「[robots.txtの設定](/aio/ai-crawler-robots-txt/)」の上級者向けの章)。AI と人のアクセスの見分け方は「[AIのアクセスと人のアクセスの違い](/aio/ai-vs-human-access/)」で図解しています。

## よくある質問

### AI検索に出るには、SEOとは別の対策が必要?

まずは SEO の基本で十分です。Google は AI Overviews と AIモードに表示されるための特別な要件はないとしています。ChatGPT や Perplexity でも、検索用のクローラーに読まれることが前提です。そのうえで、冒頭で答える書き方や一次情報など、引用されやすい中身を足していきます。

### インデックスされたら、すぐ検索結果に出る?

出るとは限りません。インデックスは「候補に入った」状態で、どの検索で何位に出るかは、検索語や数百の要因で毎回決まります。

### AIに学習されたくないけど、AI検索には出たい。できる?

できます。OpenAI なら GPTBot(学習用)だけを robots.txt で拒否し、OAI-SearchBot(検索用)は許可します。Anthropic の ClaudeBot と Claude-SearchBot も同じ考え方です。設定例は「[AIクローラーとrobots.txtの設定](/aio/ai-crawler-robots-txt/)」にあります。

### クエリ ファンアウトに合わせて、記事をたくさん分けたほうがいい?

本当に別の問いに答えるなら分けてかまいません。ただし Google は、言い回しを少し変えただけのページを大量に作ることは「大量生成コンテンツの乱用」になりうるとしています。
