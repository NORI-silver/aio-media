サイトに来るのは、人だけではありません。AI の時代になって、サイトへのアクセスは **お店に来る人のように4種類** に分けて考えるとわかりやすくなりました。

{{figure:access-shop-analogy|図1 サイトへのアクセス4種類を、お店にたとえると}}

- **お客さん**:人がブラウザ(Chrome や Safari など、ページを見るアプリ)で見に来る
- **取材の人**:AI の会社のプログラムが、AI の勉強や検索の準備のためにページを集めに来る(AI クローラー)
- **お使いの人**:人が AI に質問したときに、AI がその場でページを読みに来る
- **紹介で来た人**:AI の答えにのっていたリンクを見て、人が来る

いちばん大事なちがいは、**AI 自身のアクセスは、ふつう GA4(ジーエーフォー、Google アナリティクス:サイトに来た人の数をはかる無料の道具)に数えられない** ことです。AI の足あとが残るのは、サーバー(サイトを置いているコンピューター)の「アクセスログ」というだれがいつ来たかの記録だけです。GA4 だけを見ていると、AI がどれだけサイトを読んでいるかはわかりません。

この記事では、4種類のちがいと、それぞれの確かめ方を図で説明します。各社のボットの説明は、2026年11月9日に公式の説明で確かめました。

## サイトへのアクセスは何種類ある? [初級]

{{figure:ai-human-access|図2 サイトへのアクセス4種類と、サーバーログ・GA4での見え方}}

| | だれが来る? | 何のため? | 例 |
|---|---|---|---|
| ① 人の閲覧(お客さん) | 人 | ページを読む | 検索・SNS・ブックマークから |
| ② AI クローラー(取材の人) | AI の会社のプログラム | AI の勉強や、検索の準備のためにページを集める | GPTBot、ClaudeBot、OAI-SearchBot、PerplexityBot |
| ③ その場の取得(お使いの人) | AI の会社のプログラム | 人に質問されたときに、その場でページを読む | ChatGPT-User、Claude-User、Perplexity-User |
| ④ AI 経由の人(紹介で来た人) | 人 | AI の答えにのっていたリンクを開いて読む | ChatGPT・Perplexity・Gemini から |

②と③はどちらも AI ですが、性格がちがいます。②は前もってまとめて集めに来るもので、③は「人に頼まれたから読みに来た」ものです。OpenAI は ChatGPT-User について「自動でウェブを巡回するためには使わない」と説明しています([OpenAI のクローラー一覧](https://developers.openai.com/api/docs/bots))。Anthropic も Claude-User を、ユーザーの質問に答えるためにページを取ってくるものとしています([Anthropic の説明](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-the-web))。

④は、アクセスとしてはふつうの人と同じです。ちがうのは「どこから来たか(参照元)」だけです。

## 1つの質問でサイトには何が起きる? [初級]

{{figure:ai-access-timeline|図3 AI検索で1つの質問をしたときに、サイトに起きるアクセスの順番}}

ChatGPT の検索のような AI 検索で誰かが質問すると、サイトには次の順でアクセスが起きます。

1. **前もって**:検索用のボット(OAI-SearchBot など)がページを集めて、検索用のメモ帳(索引)に入れておく
2. **質問されたとき**:AI がメモ帳から合うページをえらんで読む。必要なら、その場でページを読みに来る(ChatGPT-User など)
3. **答えを読んだ人がリンクをクリック**:ここで初めて、人がサイトに来る

ポイントは、**AI にページが読まれて答えに使われても、人が来るのはリンクがクリックされたときだけ** ということです。サイトを守るサービスの会社 Cloudflare(クラウドフレア)が2025年8月に公開したデータでは、AI の会社のボットが読んだページの数と、その AI から人が来た回数の比(crawl-to-refer ratio)は、2025年7月時点で Anthropic が約3万8千対1、OpenAI が約1千対1、Perplexity が約195対1でした([Cloudflare Blog「The crawl-to-click gap」](https://blog.cloudflare.com/crawlers-click-ai-bots-training/)、2025年8月29日)。学習用の分もふくんだ数字ですが、「読まれる量」と「来る人の数」がけたちがいだとわかります。

## AIと人では、ページの読み方はどう違う? [中級]

| | 人(ブラウザ) | AIクローラー・AI の取得 |
|---|---|---|
| 読むもの | 画面に表示されたもの全部 | 主に HTML の文字 |
| JavaScript | 実行される | 多くは実行しない |
| 画像・CSS | 読み込む | 読み込まないことが多い |
| robots.txt | 関係ない | クローラーは従う。ユーザー代理の取得は従わないことがある |
| 読み方 | 上から順に、気になるところだけ | 質問に合う部分を探して抜き出す |

AIクローラーの多くが JavaScript を実行しないことは、Vercel と MERJ の調査(2024年12月)で確かめられています。**JavaScript を動かさないと本文が出てこないページは、人には読めても AI には空っぽに見える** ことがあります(くわしくは「[JavaScriptとAIクローラー](/aio/javascript-ai-crawlers/)」)。

robots.txt の扱いにも違いがあります。OpenAI は ChatGPT-User について「ユーザーが始めた操作なので robots.txt のルールが適用されないことがある」、Perplexity は Perplexity-User について「ユーザーの依頼による取得なので、ふつう robots.txt のルールを無視する」と書いています([Perplexity のクローラーの説明](https://docs.perplexity.ai/docs/resources/perplexity-crawlers.md))。一方 Anthropic は、Claude-User を robots.txt で止めると、ユーザーの質問に答えるためのページ取得もしなくなると説明しています。**どう扱われるかは会社ごとに違う** ので、止めたいときは各社の説明を確かめてください(設定は「[AIクローラーとrobots.txtの設定](/aio/ai-crawler-robots-txt/)」)。

AI に読まれやすくするには、人に読みやすくするのと同じく、**冒頭で答えを言い切り、見出しを問いの形にする** のが効きます。AI は質問に合う部分を抜き出して使うためです(「[冒頭で答える書き方](/aio/answer-first-writing/)」)。

## サーバーログとGA4では、どう見え方が違う? [中級]

| アクセス | サーバーのアクセスログ | GA4 |
|---|---|---|
| ① 人の閲覧 | 残る | 記録される |
| ② AIクローラー | 残る(User-Agent に GPTBot など) | ふつう記録されない |
| ③ AI のユーザー代理の取得 | 残る(User-Agent に ChatGPT-User など) | ふつう記録されない |
| ④ AI 経由の人 | 残る(Referer に chatgpt.com などが入ることがある) | 記録される(参照元が chatgpt.com など) |

GA4 に記録されないのには、2つの理由があります。

- **GA4 は JavaScript で動く**:GA4 の計測タグは、ブラウザで JavaScript が実行されたときに初めてデータを送ります。JavaScript を実行しないクローラーが HTML を取っていっても、GA4 には何も届きません。このサイトのページでも、GA4 は `<script async src="https://www.googletagmanager.com/gtag/js?id=…">` という JavaScript のタグで入っています。
- **既知のボットは自動で除かれる**:Google のヘルプによると、GA4 では既知のボットやスパイダーのアクセスは自動で除外され、この設定は止められず、どれだけ除外されたかも見られません([Known bot-traffic exclusion](https://support.google.com/analytics/answer/9888366))。

だから **「AI にどれだけ読まれているか」はサーバーログで、「AI からどれだけ人が来たか」は GA4 で** 見る、と分けて考えます。GA4 で AI からの流入を見る方法は「[AIに引用されているか確かめる方法](/aio/ai-citation-tracking/)」で説明しています。

### このサイトで確かめたこと

このサイト(AIO対策ナビ)で、2026年11月9日に次のことを確認しました。

- **本文は最初の HTML に入っている**:記事「[AI Overviewsとは?](/aio/ai-overviews/)」の HTML から本文部分の文字を数えると約4,500字あり、JavaScript を実行しなくても全文が読めます。
- **GA4 は JavaScript のタグだけで計測している**:そのため、JavaScript を実行しない AI のアクセスは GA4 に入りません。
- **このサイトにはサーバーログがない**:このサイトは GitHub Pages という静的ホスティングで公開していて、サーバーのアクセスログを見る機能がありません。そのため、AI クローラーがどれだけ来ているかは、今のところ数えられません。AI からの人の流入は GA4 で、Google のクロールは Search Console の URL 検査で見ています。

自社サイトでも、まず **自分のサーバーでアクセスログが見られるか** を確かめてください。レンタルサーバーの管理画面や、Cloudflare などの CDN のダッシュボードで見られることが多いです。

## AIエージェントのアクセスはどう見分ける? [上級]

最近は、AI がブラウザを操作してサイトを見て回る「AI エージェント」も増えています。ブラウザを実際に動かすタイプは JavaScript を実行するので、**人のアクセスと見分けがつきにくく、GA4 に記録される可能性もあります**(GA4 がエージェントをどう扱うかの公式説明は、2026年11月時点で見当たりませんでした)。

見分ける手がかりとして、OpenAI は ChatGPT エージェントのリクエストに **HTTP メッセージ署名** を付けていると説明しています([ChatGPT agent allowlisting](https://help.openai.com/en/articles/11845367-chatgpt-agent-allowlisting)、2026年11月9日に確認)。

- リクエストに `Signature` と `Signature-Input` のヘッダーが付く
- あわせて `Signature-Agent` ヘッダーが `"https://chatgpt.com"`(引用符つき)になっている
- 署名は RFC 9421 の方式で、公開鍵を使って本物か検証できる
- Cloudflare・Akamai・Vercel などのボット管理の一覧にも登録されている

User-Agent の文字列はだれでも名乗れるので、本物かどうかは **署名の検証か、各社が公開している IP アドレスの一覧** で確かめます。ログを調べるときの手順は次のとおりです。

1. アクセスログを User-Agent ごとに集計する(GPTBot、OAI-SearchBot、ChatGPT-User、ClaudeBot、Claude-User、Claude-SearchBot、PerplexityBot、Perplexity-User など)
2. 上位のものについて、IP アドレスが各社の公開一覧に入っているかを確かめる
3. ステータスコードを見る。403 や 429 が多いなら、CDN やセキュリティ設定で止めている
4. どのページがよく読まれているかを見る。読まれているのに GA4 で人が来ていないページは、回答に使われてもクリックされていない可能性がある

## よくある質問

### GA4でAIクローラーのアクセスは見られる?

ふつうは見られません。AIクローラーの多くは JavaScript を実行しないため GA4 の計測タグが動かず、既知のボットは GA4 が自動で除外もしています。AIクローラーの数を知りたいときは、サーバーのアクセスログや CDN のボット分析を使います。

### AIの回答から来た人は、GA4でどう見える?

ふつうの人の閲覧として記録され、参照元(セッションの参照元)が chatgpt.com、perplexity.ai、gemini.google.com などになります。ChatGPT からのリンクには `utm_source=chatgpt.com` が付くことがあります。

### AIクローラーをブロックすると、人のアクセスにも影響する?

人の閲覧には直接は影響しません。ただし、検索用のクローラー(OAI-SearchBot、PerplexityBot、Claude-SearchBot など)を止めると、その AI 検索の回答に出にくくなり、AI 経由で来る人は減ります。学習用(GPTBot、ClaudeBot など)だけを止めることもできます。

### AIのアクセスが増えるとサーバーの負担は増える?

巡回が増えれば、そのぶんサーバーへのリクエストも増えます。負担が気になるときは、まずアクセスログでどのクローラーがどれだけ来ているかを確かめ、、CDN のボット対策や、robots.txt で学習用だけを止める方法を検討してください。仕組みの全体像は「[SEOとAIOの仕組みを図解](/aio/how-search-and-ai-work/)」をご覧ください。
