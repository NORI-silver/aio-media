JavaScript で本文を表示するサイトは、**Google にはおおむね読まれますが、ChatGPT や Claude などのAIクローラーには読まれないおそれがあります**。Google は Googlebot がJavaScriptを実行してページを読むと説明している一方、AIクローラーは JavaScript を実行しないという調査結果が出ているためです。AI検索で引用されたいなら、**本文を最初に届くHTMLに入れておく** のが確実です。

## そもそも「JavaScriptで表示する」とは? [初級]

Web ページの表示のしかたは、大きく2つに分かれます。

| 方式 | しくみ | 最初に届くHTMLの中身 |
|---|---|---|
| **SSR・静的生成**(サーバー側で作る) | サーバーで本文まで入ったHTMLを作って送る | 本文が入っている |
| **CSR**(ブラウザ側で作る) | 空に近いHTMLを送り、ブラウザが JavaScript を実行して本文を表示する | 本文がほとんど入っていない |

人がブラウザで見ると、どちらも同じように見えます。違いが出るのは、**JavaScript を実行しないプログラム** が読んだときです。React・Vue などで作ったサイトや、ノーコードツールの一部では CSR になっていることがあります。

## 実際に試すとどう違う? [初級]

このサイトで、同じ本文を2つの方式で表示するテストページを作り、比べました(2026年11月9日)。

| | JavaScriptを実行しないで読んだ文字数 | ブラウザで表示した文字数 |
|---|---|---|
| CSR(JavaScriptで本文を表示) | 6字(ページタイトルだけ。本文は0字) | 530字 |
| 静的HTML(本文をHTMLに書く) | 40字(本文あり) | 36字 |

CSR のページは、ブラウザでは530字の本文が出ているのに、JavaScript を実行しないで読むと **本文が1字もありません**。JavaScript を実行しないクローラーからは、タイトルだけの空のページに見えるということです。

ちなみに、このサイトの記事はすべて静的なHTMLで、たとえば「[AI Overviewsとは?](/aio/ai-overviews/)」は、最初のHTMLだけで約6,000字の本文が読めます。

## GooglebotとAIクローラーは何が違う? [中級]

### Googlebot はJavaScriptを実行する

Google は、Googlebot が JavaScript のページを「クロール → レンダリング(JavaScript を実行して表示) → インデックス」の3段階で処理すると説明しています([JavaScript SEO の基本](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)、2026年3月4日更新)。ただし、

- レンダリングは順番待ちで、数秒で終わることもあれば、もっと長くかかることもある
- それでも **サーバーサイドレンダリングや事前レンダリングは「今でもよい考え」** で、ユーザーにもクローラーにも速く、**すべてのボットが JavaScript を実行できるわけではない**

とも書いています。

### AIクローラーはJavaScriptを実行しないという調査

Vercel 社と MERJ 社が2024年12月に公開した調査「[The rise of the AI crawler](https://vercel.com/blog/the-rise-of-the-ai-crawler)」では、実際のアクセスを分析した結果、**OpenAI(ChatGPT)、Anthropic(Claude)、Perplexity の主要なAIクローラーはいずれも JavaScript を実行していなかった** と報告しています。JavaScript ファイルを取得はしても(ChatGPT 約11.5%、Claude 約23.8%)、実行はしていないということです。一方、Google の Gemini は Googlebot の仕組みを使うため、JavaScript も処理されるとしています。

これは企業による調査で、各社の公式の説明ではありません。仕組みは変わることもあるので、「AIクローラーは JavaScript を実行しない前提で作っておくのが安全」と考えてください。AIクローラーの種類は「[AIクローラーのrobots.txt設定](/aio/ai-crawler-robots-txt/)」で解説しています。

## 自分のサイトはどう確かめる? [中級]

1. **[AIO診断ツール](/aio-checker/) で診断する**:「本文がHTMLに入っている」の項目で、最初のHTMLに含まれる本文の文字数を確かめられます。
2. **ブラウザで「ページのソースを表示」する**:右クリック →「ページのソースを表示」(Chrome)で、本文の文章が HTML の中にあるか探します。開発者ツールの「要素」タブは JavaScript 実行後の状態なので、確認には使いません。
3. **Search Console の URL検査で「クロール済みのページを表示」する**:Google がレンダリングした後の HTML を確認できます(Google から見えているかの確認)。

ソースに本文がなく、`<div id="root"></div>` や `<div id="app"></div>` のような空の箱しかない場合は CSR です。

## CSRのサイトはどう直す? [上級]

### 選択肢は3つ

| 方法 | 内容 | 向いている場面 |
|---|---|---|
| **静的生成(SSG)** | 公開前に全ページのHTMLを作っておく | ブログ、メディア、会社サイトなど、内容が頻繁に変わらないページ |
| **サーバーサイドレンダリング(SSR)** | アクセスのたびにサーバーで本文入りのHTMLを作る | 在庫や価格が変わる商品ページなど |
| **ハイブリッド** | 本文は HTML に入れ、検索フォームやグラフなどの動く部分だけ JavaScript で表示する | 多くのサイトの現実的な落としどころ |

Next.js、Nuxt、Astro などのフレームワークは、設定で SSR や静的生成に切り替えられます。WordPress などの一般的な CMS は、もともとサーバー側でHTMLを作るので、多くの場合は問題ありません。

### 「ダイナミックレンダリング」は回避策

クローラーにだけ別途レンダリング済みのHTMLを返す「ダイナミックレンダリング」という方法もあります。Google はこれを長期的な解決策ではなく **回避策(workaround)** と位置づけています。新しく作るなら、SSR や静的生成を選びましょう。

### JavaScript を使うときの注意点

Google の JavaScript SEO のガイドから、AI クローラーにも共通して大事な点です。

- **リンクは `<a href="...">` で書く**:クリックで JavaScript を動かすだけのボタンでは、クローラーがページを見つけられません。
- **`#` でページを切り替えない**:`/#/about` のような URL は、別のページとして扱われにくくなります。
- **存在しないページは 404 を返す**:CSR のサイトでは、存在しないページでも「200(正常)」を返してしまうことがあります。

## よくある質問

### Googleで検索に出ているなら、AIにも読まれていますか?

そうとは限りません。Googlebot は JavaScript を実行しますが、ChatGPT や Claude のクローラーは実行しないという調査があります。Google で問題なくても、AI検索では本文が読まれていない可能性があります。

### 一部だけJavaScriptで表示している場合は?

本文や、答えになる大事な情報が HTML に入っていれば大きな問題はありません。JavaScript で表示している部分(タブの中身、「もっと見る」で開く部分など)に大事な情報がないかを確かめましょう。

### 画像の中の文字はAIに読まれますか?

確実ではありません。Google も、重要な情報は画像の中だけでなくテキストで書くよう勧めています。料金表や手順などは、HTML のテキストや表で書きましょう。

### llms.txtを置けばJavaScriptの問題は解決しますか?

解決しません。llms.txt はサイトの案内板のようなもので、各ページの本文を代わりに届けるものではありません。詳しくは「[llms.txtとは?](/glossary/llms-txt/)」をご覧ください。
