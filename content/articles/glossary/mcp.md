MCP(エムシーピー、Model Context Protocol)は、**Claude や ChatGPT などの AI アプリを、外部のツールやデータにつなぐためのオープンな共通規格** です。公式サイトでは「AI アプリのための USB-C ポートのようなもの」と説明されています([What is MCP?](https://modelcontextprotocol.io/docs/getting-started/intro)、2026年11月9日に確認)。

USB-C の機器ならどのパソコンにも挿せるように、MCP の決まりに沿って作った「MCP サーバー」は、MCP に対応したいろいろな AI アプリから使えます。SEO・AIO の仕事でいえば、**AI に「先月クリックが減ったページは?」と聞くだけで、AI が Search Console や GA4 のデータを取りに行って答えてくれる** ようになります。このサイトの運営でも実際にそうしています。

## MCPをひとことで言うと? [初級]

MCP は、**AI が外の道具を使うときの「共通の差し込み口」** です。

これまでは、AI アプリごとに「Search Console とつなぐ仕組み」「GA4 とつなぐ仕組み」を別々に作る必要がありました。MCP があると、道具の側は MCP サーバーを1つ作れば、Claude・ChatGPT・VS Code・Cursor など MCP に対応したアプリから同じように使えます(対応アプリの例は[公式サイト](https://modelcontextprotocol.io/docs/getting-started/intro)による)。

| よくある誤解 | 実際 |
|---|---|
| AI の新しいモデルの名前 | AI と道具をつなぐ **決まり(プロトコル)** の名前 |
| 1社だけの独自の仕組み | オープンな規格。Anthropic が2024年11月に公開し、2025年12月に Linux Foundation のもとの Agentic AI Foundation に寄贈された |
| サイトの SEO に直接効く | 検索順位や AI Overviews とは直接関係ない(後で説明) |

出典:[Anthropic「Introducing the Model Context Protocol」](https://www.anthropic.com/news/model-context-protocol)(2024年11月25日)、[Anthropic「Donating the Model Context Protocol and establishing the Agentic AI Foundation」](https://www.anthropic.com/news/donating-the-model-context-protocol-and-establishing-of-the-agentic-ai-foundation)(2025年12月9日)。寄贈の発表では、公開されている MCP サーバーが1万以上あるとされています。

## MCPはどんな仕組みで動く? [初級]

{{figure:mcp-architecture|図1 MCPの構成。AIアプリ(ホスト)が、つなぐサーバーごとにクライアントを持つ}}

MCP には3つの役割があります([MCP の構成の説明](https://modelcontextprotocol.io/docs/learn/architecture)、2026年11月9日に確認)。

- **MCP ホスト**:人が使う AI アプリ(Claude、ChatGPT、VS Code など)
- **MCP クライアント**:ホストの中で、MCP サーバー1つとやりとりする係。サーバーごとに1つずつできる
- **MCP サーバー**:道具やデータを AI に提供するプログラム。たとえば「Search Console のデータを取る」サーバー

サーバーが AI に差し出すものは、主に次の3種類です。

| 種類 | 中身 | SEO の仕事での例 |
|---|---|---|
| ツール(tools) | AI が呼び出せる操作 | 「URL のインデックス状況を調べる」「検索クエリの表を取る」 |
| リソース(resources) | AI が読める資料・データ | サイトの記事一覧、作業ルールの文書 |
| プロンプト(prompts) | よく使う指示のひな形 | 「月次レポートを作る」手順 |

## SEO・AIOの仕事ではどう使う? [中級]

{{figure:mcp-gsc-flow|図2 MCPでAIがSearch Consoleのデータを使って答えるまでの流れ}}

AI に質問すると、AI は MCP サーバーの「ツールの一覧」から使う道具を選び、サーバーが Search Console などの API を呼んで結果を返し、AI がそれを読んで答えます。人は API の使い方や画面の操作を知らなくても、言葉で聞くだけで済みます。

### このサイトでの実例

このサイト(AIO対策ナビ)の運営では、Search Console と GA4 につながる MCP サーバーを使っています。たとえば記事「[SEOとAIOの仕組みを図解](/aio/how-search-and-ai-work/)」を書くときに、AI から MCP 経由で Search Console の URL 検査を呼び、次の結果を得ました(2026年11月9日)。

| 調べたこと | MCP 経由で返ってきた結果 |
|---|---|
| トップページのインデックス状況 | 「送信して登録されました」、robots.txt は許可、最終クロール 2026年11月9日、Google が選んだ正規URLとサイトの指定が一致 |
| 記事ページのインデックス状況 | 「検出 - インデックス未登録」(URL は見つかったがまだクロールされていない) |

画面で1ページずつ開くと手間のかかる確認が、会話の中で数秒で終わります。ほかにも、検索クエリの集計、GA4 の参照元別の流入(AI からの流入を含む)などを同じように呼び出しています。調べ方そのものは「[Search Consoleの始め方](/seo/search-console-start/)」「[AIに引用されているか確かめる方法](/aio/ai-citation-tracking/)」で解説しています。

使ってみてわかった注意点は2つです。

- **API には1日の上限がある**:Search Console の URL 検査は回数の上限があるので、全ページを毎日調べるような使い方には向きません。必要なページだけに絞っています。
- **AI の説明はかならず元の数字で確かめる**:AI は返ってきた数字をもとに「原因の候補」を挙げますが、推測が混じります。判断の前に、元の表や Search Console の画面を確認しています。

## MCPを使うときの安全面の注意は? [中級]

MCP サーバーは、あなたの代わりにデータを読んだり操作したりできます。便利なぶん、つなぐ相手と権限には注意が必要です。公式の[セキュリティのベストプラクティス](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices.md)(2026年11月9日に確認)をもとに、実務での目安をまとめます。

- **信頼できる提供元のサーバーだけを入れる**:自分のパソコンで動くサーバーは、パソコンの中のファイルなどにアクセスできることがあります。仕様の文書でも、ローカルで動くサーバーには利用者の同意やサンドボックス(隔離)が必要だとしています。
- **権限は必要な分だけ**:Search Console なら「読み取りだけ」で足りるなら、書き込みの権限は渡しません。仕様の文書も、権限(スコープ)を最小にすることをすすめています。
- **書き込み・削除・送信の操作は、実行前に確認する設定にする**:AI が間違った操作を選ぶこともあるためです。
- **API キーやトークンを記事・リポジトリ・共有の場所に書かない**:このサイトのリポジトリも公開なので、鍵はリポジトリの外で管理しています。

## サイトが「MCPに対応する」とはどういうこと? [中級]

最近は「自社サイトを MCP 対応にしましょう」という話も聞くようになりました。これは、**自社のデータや機能を MCP サーバーとして公開し、AI アプリから直接使えるようにする** ことを指します。たとえば、ネットショップの商品検索・在庫確認、予約サイトの空き状況、ソフトウェアのドキュメント検索などです。

ただし、次の点ははっきり分けて考えてください。

- **MCP 対応は、Google 検索の順位や AI Overviews への表示とは関係ありません**。Google は、AI 機能に表示されるために特別な仕組みは必要ないとしています([AI features and your website](https://developers.google.com/search/docs/appearance/ai-features))。AI 検索に出るための対策は、まず「[SEOとAIOの仕組み](/aio/how-search-and-ai-work/)」で説明した基本です。
- ChatGPT や Claude のような AI アプリでは、利用者が自分でその MCP サーバー(コネクタ)を追加したときに使われます。作っただけで、AI がかってに見つけて使うわけではありません。
- 中小企業の会社案内サイトやブログなら、**今すぐ必要なものではありません**。予約・在庫・料金表のように「AI から直接聞かれる・操作されると便利なデータ」がある事業で、検討する価値が出てきます。

## MCPの仕様をもう一歩くわしく知るには? [上級]

自分で MCP サーバーを作る、または導入を判断する立場の人向けに、仕様のポイントをまとめます([MCP の構成の説明](https://modelcontextprotocol.io/docs/learn/architecture)と[仕様の最新版](https://modelcontextprotocol.io/specification/latest)、2026年11月9日に確認。最新版は 2026-07-28 版)。

- **やりとりの形式**:JSON-RPC 2.0 という決まった形式のメッセージでやりとりします。
- **つなぎ方(トランスポート)は2種類**:
  - **stdio**:同じパソコンの中でプログラム同士がつながる。自分専用のサーバー向け。
  - **Streamable HTTP**:ネット越しにつながる。リモートのサーバー向けで、認証には OAuth が推奨されています。
- **2026-07-28 版での変更**:サーバーが接続ごとの状態を持たなくてよい(ステートレス)形が基本になり、サーバーの機能を問い合わせる `server/discover` が加わりました。一方で、サーバーから AI に文章生成を頼む sampling などは非推奨(deprecated)になっています。古い記事の説明とは違うことがあるので、作る前に必ず最新版の仕様を確認してください。

### セキュリティで押さえる用語

公式のベストプラクティスでは、次のような攻撃や失敗の例が挙げられています。

| 用語 | 何が起きる? | 対策の方向 |
|---|---|---|
| 混乱した代理(confused deputy) | サーバーが持つ強い権限を、別の利用者のために使ってしまう | 利用者ごとに同意を取り、許可を確かめる |
| トークンのたらい回し(token passthrough) | 受け取ったトークンをそのまま別の API に渡す | 仕様で禁止。サーバー自身のトークンを正しく取る |
| SSRF | サーバーに社内のネットワークなど、意図しない場所へアクセスさせる | アクセス先を制限する |
| ローカルサーバーの乗っ取り | 怪しいサーバーやコマンドが自分のパソコンで動く | 実行前の確認、サンドボックス |

SEO の担当者が自分で作らない場合でも、導入するサーバーが「どの権限を求めているか」「どこにデータを送るか」は必ず確かめてください。

## よくある質問

### MCPを使うのにプログラミングは必要?

使うだけなら、ほとんど必要ありません。Claude や ChatGPT では、設定画面からコネクタ(MCP サーバー)を追加して使えます。自分の会社専用のサーバーを作る場合はプログラミングが必要です。

### MCPとAPIは何が違う?

API は、それぞれのサービスが用意している個別の窓口です。MCP は、AI アプリがいろいろな API や道具を **同じやり方で** 使えるようにするための共通の決まりです。多くの MCP サーバーは、裏側でサービスの API を呼んでいます。

### MCPに対応するとAI検索で引用されやすくなる?

なりません。Google 検索(AI Overviews・AIモードを含む)の表示は、通常の検索と同じ仕組みで決まります。ChatGPT などの AI 検索で引用されるかも、主に検索用のクローラーに読まれるかと、ページの中身で決まります。対策の順番は「[AIO・LLMO・GEO・AEOの違い](/aio/aio-llmo-geo-aeo-difference/)」をご覧ください。

### MCPとllms.txtは関係ある?

別のものです。[llms.txt](/glossary/llms-txt/) はサイトの概要を AI に案内するテキストファイル、MCP は AI がツールやデータを操作・取得するための通信の決まりです。
