MCP(エム・シー・ピー)は、**AI を、ほかの道具やデータにつなぐための「みんなで決めた共通のつなぎ方」** です。正式な名前は Model Context Protocol(モデル・コンテキスト・プロトコル)といいます。

たとえるなら、**USB-C の差し込み口** です。USB-C の形をしていれば、どの会社のパソコンにも、どの会社の機器でもさせますよね。MCP も同じで、MCP の形で作った道具は、Claude でも ChatGPT でも、MCP に対応した AI ならどれからでも使えます。公式サイトでも「AI アプリのための USB-C ポートのようなもの」と説明されています(出典:[What is MCP?](https://modelcontextprotocol.io/docs/getting-started/intro)、2026年11月9日に確認)。

MCP を使うと、たとえば AI に「このページ、Google に登録された?」と聞くだけで、AI が Google の道具(Search Console)にたずねに行って、答えを教えてくれます。このサイトの運営でも、実際にそうやって使っています。

## MCPってなに? [初級]

{{figure:mcp-analogy|図1 MCPはUSB-Cのようなもの。共通の形なので、どれとでもつながる}}

AI はとてもかしこいですが、そのままでは **自分の外にあるもの** にさわれません。たとえば、あなたのサイトが Google 検索でどれくらい見られているかは、Google の「Search Console(サーチコンソール)」という道具の中にあって、AI はそのままでは見られません。

そこで、AI と道具のあいだをつなぐ「つなぎ方」が必要になります。

{{figure:mcp-before-after|図2 MCPがないときと、あるときのちがい}}

MCP ができる前は、AI と道具の **組み合わせごとに、べつべつのつなぎ方** を作る必要がありました。AI が3つ、道具が3つあれば、3×3で9通りです。

MCP があると、AI も道具も「MCP の形」に合わせるだけで、どれとでもつながります。これが MCP のいちばん大事なところです。

MCP は、Claude を作っている Anthropic(アンソロピック)という会社が2024年11月に発表し、2025年12月からは、いろいろな会社が参加する団体(Linux Foundation の Agentic AI Foundation)で育てられています。だれでも使える、ひらかれたルールです(出典:[Anthropic「Introducing the Model Context Protocol」](https://www.anthropic.com/news/model-context-protocol)、2024年11月25日。[Anthropic「Donating the Model Context Protocol and establishing the Agentic AI Foundation」](https://www.anthropic.com/news/donating-the-model-context-protocol-and-establishing-of-the-agentic-ai-foundation)、2025年12月9日)。

## MCPはどうやって動く? [初級]

{{figure:mcp-architecture|図3 MCPのしくみ。AIアプリの中の「つなぎ係」が、道具ごとの窓口(MCPサーバー)と話す}}

MCP には、3つの役があります(出典:[MCP の構成の説明](https://modelcontextprotocol.io/docs/learn/architecture)、2026年11月9日に確認)。

| 役 | やさしく言うと | 正式な名前 |
|---|---|---|
| 人が使う AI | Claude や ChatGPT など、あなたが話しかける AI | MCP ホスト |
| つなぎ係 | AI の中で、窓口1つと話す係。窓口ごとに1人いる | MCP クライアント |
| 道具の窓口 | 道具やデータを AI に使わせてくれるプログラム | MCP サーバー |

「サーバー」というと大きな機械を思いうかべるかもしれませんが、ここでは **「道具の窓口になってくれるプログラム」** のことです。自分のパソコンの中で動くものも、インターネットの向こうで動くものもあります。

### 窓口がAIにわたせる3つのもの

{{figure:mcp-three-things|図4 MCPサーバーがAIにわたせる3つのもの}}

1. **やってくれること(ツール)**:AI が「これやって」と呼び出せる操作です。例:「このページが Google に登録されているか調べる」。
2. **読める資料(リソース)**:AI が読んで参考にできるデータです。例:サイトの記事の一覧。
3. **お願いのひな形(プロンプト)**:よく使うお願いの決まった形です。例:「今月のまとめを作って」。

## SEO・AIOの仕事ではどう使う? [初級]

{{figure:mcp-gsc-flow|図5 AIがMCPでSearch Consoleにたずねて、答えるまで}}

人が AI に質問すると、AI は窓口の「やってくれることの一覧」から合うものをえらびます。窓口(MCP サーバー)が Search Console にたずねて、結果を AI にわたし、AI がわかりやすい言葉で答えてくれます。人は、むずかしい画面の使い方を知らなくても大丈夫です。

### このサイトで実際に使ってみた

このサイト(AIO対策ナビ)の運営では、Search Console と GA4(Google アナリティクス、サイトに来た人の数をはかる道具)につながる MCP サーバーを使っています。記事「[SEOとAIOの仕組みを図解](/aio/how-search-and-ai-work/)」を書いたときは、AI に聞いて、MCP 経由でページの登録状況を調べました(2026年11月9日)。

| 調べたページ | MCP 経由で返ってきた答え | やさしく言うと |
|---|---|---|
| トップページ | 「送信して登録されました」。2026年11月9日に Google が読みに来ていた | Google のメモ帳にのっている |
| 記事のページ | 「検出 - インデックス未登録」 | あることは知られているが、まだ読みに来ていない |

画面で1ページずつ開いて調べると時間がかかることが、会話の中で数秒で終わりました。ほかにも、検索された言葉の集計や、AI からサイトに来た人の数などを同じように調べています。調べ方そのものは「[Search Consoleの始め方](/seo/search-console-start/)」「[AIに引用されているか確かめる方法](/aio/ai-citation-tracking/)」で説明しています。

使ってみてわかった注意点は2つです。

- **1日に使える回数に上限がある**:Search Console のページの登録状況を調べる機能には、1日の回数の上限があります。全部のページを毎日調べるような使い方には向かないので、必要なページだけ調べています。
- **AI の説明は、元の数字でたしかめる**:AI は数字をもとに「たぶんこれが原因です」と教えてくれますが、推測もまじります。決める前に、元の表や Search Console の画面を見るようにしています。

## MCPを安全に使うには? [中級]

MCP の窓口は、あなたの代わりにデータを見たり、操作したりできます。便利なぶん、**家のカギをあずけるのと同じくらい** 気をつけましょう。

{{figure:mcp-safety|図6 MCPを安全に使う4つの約束}}

1. **知っている相手だけつなぐ**:信頼できる会社や人が作った窓口だけを使います。自分のパソコンで動く窓口は、パソコンの中のファイルにさわれることもあるからです。
2. **カギは必要な分だけわたす**:データを見るだけでいいなら、「見る」だけの許可にします。書きかえる許可までわたしません。
3. **大事な操作は確認してから**:消す・送る・書きかえる、といった操作は、AI が実行する前に人が確認する設定にします。AI がまちがった操作をえらぶこともあるからです。
4. **カギを人に見せない**:パスワードや「API キー」(道具を使うための合言葉)を、記事や共有の場所に書きません。このサイトのプログラムは公開しているので、カギはその外で管理しています。

これらは、MCP の公式の[セキュリティのベストプラクティス](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices.md)(2026年11月9日に確認)の考え方を、やさしく言いかえたものです。

## サイトが「MCPに対応する」ってどういうこと? [中級]

最近は「サイトを MCP に対応させましょう」という話も聞くようになりました。

{{figure:mcp-site-support|図7 Webページは人が見る入口、MCPサーバーはAIが使う窓口}}

これは、**人が見るための Web ページとはべつに、AI が使うための窓口(MCP サーバー)を用意する** ということです。たとえば、ネットショップの「商品をさがす・在庫を調べる」、予約サイトの「空いている日を調べる」を、AI から直接使えるようにする、といった使い方です。

ただし、まちがえやすい点が3つあります。

- **MCP に対応しても、検索の順位や AI の答えに出やすくはなりません**。Google は、AI の答え(AI Overviews など)に出るために、とくべつなしくみは必要ないとしています(出典:[AI features and your website](https://developers.google.com/search/docs/appearance/ai-features))。出るための工夫は「[SEOとAIOの仕組み](/aio/how-search-and-ai-work/)」で説明した基本です。
- **作っただけで AI がかってに使うわけではありません**。Claude や ChatGPT では、使う人が自分で、その窓口(コネクタ)を追加したときに使われます。
- **小さな会社の紹介サイトやブログなら、いますぐ必要なものではありません**。予約・在庫・料金のように「AI から直接たずねられると便利なデータ」がある場合に、考える価値が出てきます。

## もっとくわしく知りたい人へ:仕様とセキュリティの用語 [上級]

自分で MCP サーバーを作る人や、導入を判断する人向けに、仕様のポイントをまとめます(出典:[MCP の構成の説明](https://modelcontextprotocol.io/docs/learn/architecture)、[仕様の最新版](https://modelcontextprotocol.io/specification/latest)、2026年11月9日に確認。最新版は 2026-07-28 版)。

- **やりとりの形式**:JSON-RPC 2.0 という決まった形式のメッセージでやりとりします。
- **つなぎ方(トランスポート)は2種類**:
  - **stdio**:同じパソコンの中でプログラム同士がつながる。自分専用のサーバー向け。
  - **Streamable HTTP**:インターネット越しにつながる。リモートのサーバー向けで、認証には OAuth がすすめられています。
- **2026-07-28 版での変更**:サーバーが接続ごとの状態を持たなくてよい(ステートレス)形が基本になり、サーバーの機能を問い合わせる `server/discover` が加わりました。一方で、サーバーから AI に文章の生成を頼む sampling などは非推奨(deprecated)になっています。古い解説とはちがうことがあるので、作る前に最新版の仕様を確認してください。
- **広がり**:公式サイトでは、Claude・ChatGPT・VS Code・Cursor などが MCP に対応しているとしています。Agentic AI Foundation への寄贈の発表(2025年12月)では、公開されている MCP サーバーが1万以上あるとされています。

### セキュリティで押さえる用語

| 用語 | 何が起きる? | 対策の方向 |
|---|---|---|
| 混乱した代理(confused deputy) | サーバーが持つ強い権限を、べつの利用者のために使ってしまう | 利用者ごとに同意を取り、許可をたしかめる |
| トークンのたらい回し(token passthrough) | 受け取ったトークンを、そのままべつの API にわたす | 仕様で禁止。サーバー自身のトークンを正しく取る |
| SSRF | サーバーに、社内のネットワークなど意図しない場所へアクセスさせる | アクセス先を制限する |
| ローカルサーバーの乗っ取り | あやしいサーバーやコマンドが自分のパソコンで動く | 実行前の確認、サンドボックス(隔離) |
| スコープの最小化 | 権限を広くわたしすぎると、被害が大きくなる | 必要な権限(スコープ)だけを求める・わたす |

自分で作らない場合でも、導入する窓口が「どの権限を求めているか」「データをどこに送るか」は、かならずたしかめてください。

## よくある質問

### MCPを使うのにプログラミングは必要?

使うだけなら、ほとんどいりません。Claude や ChatGPT では、設定の画面からコネクタ(MCP の窓口)を追加して使えます。自分の会社専用の窓口を作るときは、プログラミングが必要です。

### MCPとAPIは何がちがう?

API(エー・ピー・アイ)は、それぞれのサービスが用意している「そのサービス専用の窓口」です。MCP は、AI がいろいろな API や道具を **同じやり方で** 使えるようにするための共通のつなぎ方です。多くの MCP サーバーは、うしろでサービスの API を呼んでいます。

### MCPに対応するとAI検索で紹介されやすくなる?

なりません。Google の AI の答えへの出方は、ふつうの検索と同じしくみで決まります。ChatGPT などの AI 検索で紹介されるかも、ページを読みに来るプログラムに読まれるかと、ページの中身で決まります。やることの順番は「[AIO・LLMO・GEO・AEOの違い](/aio/aio-llmo-geo-aeo-difference/)」をご覧ください。

### MCPとllms.txtは関係ある?

べつのものです。[llms.txt](/glossary/llms-txt/) はサイトの内容を AI に案内するテキストファイル、MCP は AI が道具やデータを使うための共通のつなぎ方です。
