canonical(カノニカル)とは、**同じ内容のページが複数のURLで見られるときに、「代表はこのURLです」と検索エンジンに伝えるための指定** です。日本語では「正規URL」と呼ばれます。Google は、canonical の指定を「強い手がかり(シグナル)」として扱いますが、必ずそのとおりになるとは限りません。

この記事では、Google 検索セントラルの「[重複した URL を統合する](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)」(2026年7月10日更新)をもとに、canonical の書き方と整理のしかたを解説します。

## なぜ同じページが複数のURLになる? [初級]

自分では1ページしか作っていなくても、URL は意外と簡単に増えます。

| 例 | URL |
|---|---|
| www の有無 | `https://example.com/` と `https://www.example.com/` |
| http と https | `http://example.com/` と `https://example.com/` |
| 末尾のスラッシュ | `/page` と `/page/` |
| 広告やメールの計測用パラメータ | `/page/?utm_source=mail` |
| 並べ替え・絞り込み | `/items/?sort=price` |
| 印刷用・スマホ用ページ | `/page/print/` |

検索エンジンから見ると、これらは別々のURLです。どれを検索結果に出すべきかを伝えないと、評価が分散したり、意図しないURLが表示されたりします。

## canonicalはどう書く? [中級]

いちばん一般的なのは、ページの `<head>` に `link` タグを書く方法です。

```
<link rel="canonical" href="https://aio.shiokonbu.com/seo/canonical-url/">
```

このサイトでは、全ページにこの形の canonical を自動で入れています。ポイントは3つです。

- **絶対URL(https:// から始まる完全なURL)で書く**:Google は相対パス(`/seo/...`)ではなく絶対URLを勧めています。
- **自分自身を指してよい**:重複がないページでも、自分のURLを canonical にしておくと、計測用パラメータ付きのURLなどから代表のURLがはっきりします。
- **1ページに1つだけ**:複数あると、どれが正しいか伝わりません。

PDF のように HTML ではないファイルは、HTTP ヘッダーで `Link: <https://example.com/doc.pdf>; rel="canonical"` のように指定できます。

## リダイレクトやサイトマップとどう使い分ける? [中級]

Google は、代表URLを伝える方法として次の3つを挙げ、強さを次のように説明しています。

| 方法 | 強さ | 向いている場面 |
|---|---|---|
| リダイレクト(301など) | 強い | 古いURLを使わなくなったとき。http→https、www の統一など |
| `rel="canonical"` | 強い | 両方のURLを残す必要があるとき(計測用パラメータ、並べ替えなど) |
| サイトマップに載せる | 弱い | 補助。代表URLだけをサイトマップに載せる |

**古いURLを見せる必要がないならリダイレクト、見せる必要があるなら canonical** と覚えておくと迷いません。どの方法でも、指す先をそろえることが大切です。サイトマップの作り方は「[XMLサイトマップとは?](/seo/xml-sitemap/)」で解説しています。

## やってはいけない間違いは? [中級]

Google のガイドが挙げている、よくある間違いです。

- **robots.txt で重複ページをブロックする**:robots.txt でクロールを止めても、内容なしでURLだけがインデックスされることがあります。canonical も読まれなくなります([robots.txtの設定](/aio/ai-crawler-robots-txt/))。
- **noindex で代表を選ぼうとする**:noindex はページを検索から完全に外す指定です。代表URLを選ぶ目的には使いません。
- **方法ごとに違うURLを指す**:サイトマップには A、canonical には B、のように食い違うと、Google が判断できません。
- **URLの `#` 以降(フラグメント)を canonical にする**
- **相対パスで書く**
- **URL削除ツールで重複を消そうとする**:そのURLのすべてのバージョンが検索から一時的に消えてしまいます。

## Googleがどのページを代表に選んだか確かめるには? [上級]

canonical は「お願い」なので、Google が別のURLを選ぶこともあります。実際にどのURLが選ばれたかは、Search Console の **URL検査** で確かめます。表示される項目は2つです。

- **ユーザーが指定した正規URL**:canonical タグ、HTTP ヘッダー、サイトマップから読み取った、サイト側の指定
- **Google が選択した正規URL**:Google が実際に代表として選んだURL

このサイトのトップページを2026年11月9日に URL検査で確かめた結果は、次のとおりでした。

| 項目 | 結果 |
|---|---|
| 登録状況 | 送信して登録されました |
| ユーザーが指定した正規URL | `https://aio.shiokonbu.com/` |
| Google が選択した正規URL | `https://aio.shiokonbu.com/` |
| 最終クロール | 2026年11月9日 |

2つが一致していれば、指定どおりに扱われています。一致しない場合、Google は似たページと比べて別のURLのほうがふさわしいと判断しています。たとえば、内容がほとんど同じページが複数ある、内部リンクが別のURLに向いている、サイトマップに別のURLが載っている、といった原因が考えられます。

### Googleは何を見て代表を選ぶ?

canonical の指定がない場合も、Google は「ユーザーに見せるのに最もふさわしいURL」を自動で選びます。そのとき、**http より https** を、**hreflang(多言語ページの対応づけ)で指定されたURL** を優先する、といった傾向があると説明しています。指定が食い違っていたり、内部リンクやサイトマップが別のURLを指していたりすると、指定したURLが選ばれにくくなります。canonical タグ・内部リンク・サイトマップ・リダイレクトの4つを、同じURLにそろえるのが確実です。

自分のサイトに canonical が入っているかは、[AIO診断ツール](/aio-checker/) で確かめられます。

## よくある質問

### canonicalを入れると検索順位は上がる?

canonical そのものが順位を上げるわけではありません。重複したURLに分かれていた評価や計測データを、1つのURLにまとめるための仕組みです。

### 全ページに自分自身を指すcanonicalを入れるべき?

入れておくのがおすすめです。計測用パラメータ付きのURLや、末尾のスラッシュの違いなどで、意図しないURLが検索結果に出るのを防ぎやすくなります。

### Googleが選んだURLが自分の指定と違うときは?

まず、canonical タグ・内部リンク・サイトマップ・リダイレクトが同じURLを指しているかを確かめます。そろえたうえで、ページを修正したら URL検査からクロールを依頼し、反映を待ちます。
