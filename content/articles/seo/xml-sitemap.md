XMLサイトマップとは、**サイトにあるページのURLと更新日を一覧にして、検索エンジンに「このサイトにはこのページがあります」と伝えるためのファイル** です。Google は、サイトマップを送っても必ずクロールされるわけではない「ヒント」だとしつつ、ページを見つけてもらう助けになると説明しています。

この記事では、Google 検索セントラルの「[サイトマップの作成と送信](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)」(2026年7月8日更新)をもとに、作り方と送り方を解説します。


たとえるなら、サイトマップは **建物の「部屋の一覧表」** です。Google の見回り役(Googlebot:グーグルボット)は、ふだんは廊下(ページの中のリンク)をたどって部屋(ページ)を見つけます。でも、どこからも廊下がつながっていない部屋は見落としがちです。そこで「この建物にはこの部屋があります」という一覧表をわたしておくと、見つけてもらいやすくなります。

{{figure:sitemap-floor|図1 リンクがつながっていないページは見落とされやすい。サイトマップは部屋の一覧表}}

ただし、一覧表をわたしても、見回り役がすぐに全部の部屋に来てくれるとは限りません。どの部屋にいつ行くかは、Google が決めます。

## サイトマップは必要? [初級]

検索エンジンは、ふだんはページの中のリンクをたどって新しいページを見つけます。そのため、内部リンクでしっかりつながっている小さなサイトなら、サイトマップがなくても見つけてもらえることが多いです。

それでも、次のようなサイトでは用意しておく価値があります。

- **公開したばかりで、外部からのリンクがほとんどない**
- **ページ数が多い**、または **どこからもリンクされていないページがある**
- **記事を頻繁に追加・更新する**

WordPress なら、標準機能や SEO プラグインで自動で作られていることが多いので、まず `https://自分のドメイン/sitemap.xml` などを開いて、すでにあるか確かめましょう。

## どう書けばいい? [中級]

このサイトの実際の [sitemap.xml](/sitemap.xml) の先頭です(記事を公開するたびに自動で作り直しています)。

```
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
<url><loc>https://aio.shiokonbu.com/</loc><lastmod>2026-11-09</lastmod></url>
<url><loc>https://aio.shiokonbu.com/aio/ai-overviews/</loc><lastmod>2026-11-09</lastmod></url>
<url><loc>https://aio.shiokonbu.com/seo/structured-data/</loc><lastmod>2026-11-09</lastmod></url>
</urlset>
```

- `<loc>`:ページのURL。**https:// から始まる完全なURL** で書きます。
- `<lastmod>`:ページを最後に大きく更新した日。

Google が守るよう求めているルールは次のとおりです。

| ルール | 内容 |
|---|---|
| 上限 | 1ファイルにつき **5万URL または 50MB(圧縮前)** まで。超える場合は分割する |
| URL | 絶対URLで書く |
| 載せるURL | 検索に出したい代表URL([canonical](/seo/canonical-url/) と同じもの)だけ |
| 形式 | XML のほか、RSS・Atom、URLを1行ずつ並べたテキストファイルも使える |

このサイトでは、記事のないカテゴリページなど noindex のページはサイトマップに載せないようにしています。「検索に出さない」と指定したページを「見つけてください」と送るのは矛盾するからです。

## Search Consoleへはどう送る? [中級]

サイトマップを Google に知らせる方法は主に2つです。

1. **Search Console の「サイトマップ」レポートで送信する**:サイトマップのURLを入力して送信します。Google がいつ読み込んだか、エラーがないかも確認できます。
2. **robots.txt に1行書く**:`Sitemap: https://example.com/sitemap.xml` と書いておくと、Google が次に robots.txt を読んだときに見つけます。このサイトの [robots.txt](/robots.txt) にも入っています。

両方やっておくと確実です。Search Console をまだ使っていない場合は「[Search Consoleの始め方](/seo/search-console-start/)」を参考にしてください。

## lastmodやpriorityはどう扱われる? [上級]

### priority と changefreq は無視される

サイトマップの仕様には、ページの重要度を表す `<priority>` と、更新頻度を表す `<changefreq>` もあります。しかし Google は **この2つを無視する** と明記しています。わざわざ設定する必要はありません。

### lastmod は「正確なときだけ」使われる

`<lastmod>` について、Google は **一貫して正確だと確認できる場合にだけ使う** としています。ここでいう「更新」は、本文、構造化データ、リンクなどの大事な変更のことです。フッターの著作権表示の年を変えただけ、といった変更で日付を新しくしてはいけません。

全ページの lastmod を毎日「今日」にするような作り方をしていると、Google に「このサイトの lastmod は信用できない」と判断され、本当に更新したページの情報まで使われなくなるおそれがあります。このサイトでは、記事の lastmod に記事ごとの「更新日(updated)」を使い、記事を実際に直したときだけ変えるようにしています。

### 大きなサイトはサイトマップインデックスで分ける

5万URLを超える場合や、記事・商品・カテゴリなど種類ごとに分けて管理したい場合は、複数のサイトマップをまとめる「サイトマップインデックス」ファイルを作り、それを送信します。種類ごとに分けておくと、Search Console でどの種類のページが登録されていないかを見分けやすくなります。

### 送っても登録されるとは限らない

このサイトでは公開当日(2026年11月9日)にサイトマップを用意しましたが、同日の時点でトップページは登録済み、記事の一部は「検出 - インデックス未登録」(見つかったが、まだクロール・登録されていない状態)でした。サイトマップはあくまで「見つけてもらう」ための手段で、登録されるかどうかはページの中身やサイトの評価で決まります。

自分のサイトにサイトマップがあるかは、[AIO診断ツール](/aio-checker/) でも確かめられます。

## よくある質問

### サイトマップを送ればすぐに検索に出る?

すぐには出ません。Google はサイトマップを「ヒント」として扱い、送っても読み込まれない、クロールされないこともあると説明しています。新しいページを早く見てほしいときは、Search Console の URL検査からインデックス登録をリクエストする方法もあります。

### HTMLのサイトマップ(ページ一覧のページ)とは違う?

違います。XMLサイトマップは検索エンジン向けのファイルで、HTMLのサイトマップは人が読むためのページです。目的が違うので、どちらか一方で代わりにはなりません。

### 画像や動画もサイトマップに載せられる?

載せられます。Google は画像・動画・ニュース用の拡張形式に対応しています。画像や動画が検索から見つけにくい作りのサイトでは検討してください。

### 削除したページはサイトマップから外すべき?

外してください。存在しないURLや、リダイレクトするURL、noindex のURLは載せないのが基本です。
